================================================================================
VN-IPFS ARCHITECTURAL TRANSFORMATION PLAN
================================================================================
Problem Statement: Current implementation uses CID-based storage with DHT routing
of provider announcements. New requirements demand key-based storage where:
- Key = hash(data) only (no provider ID in hash)
- DHT routes tokens (containing physical locations), not data directly
- Routing table stores [key, ProviderID] with multiple providers per key
- Gateway layer for query optimization
- Key-level locking for write operations

Reference Documents:
- newReqs.txt (new architectural requirements)
- architecture.txt (vn-IPFS Architecture v1.4)
- plan.txt (current implementation plan)

================================================================================
PHASE 1: KEY-BASED STORAGE FOUNDATION
================================================================================
Goal: Transform from CID-based to key-based storage where key = hash(data).

1.1 Key Generation and Storage
    ---------------------------
    File: internal/storage/key.go (new)
    
    Current: Uses CID (content-addressed) for storage
    Required: Use key = hash(data) for storage, with provider ID attached separately
    
    Tasks:
    [x] Define Key type: hash of data (SHA256)
    [x] Implement KeyFromData(data []byte) Key function
    [x] Store key as primary identifier (CID derived from data for IPFS blockstore compatibility)
    [x] Update PutRawBlockIndexed to generate and store key
    [x] Update routing table to use Key as primary identifier (not CID)
    
    Key Structure:
    - Key: []byte (SHA256 hash of data)
    - ProviderID: peer.ID (attached to key, not in hash)
    - Data: []byte (actual content)
    - CID: cid.Cid (for IPFS compatibility, derived from data)

1.2 Routing Table Transformation
    -----------------------------
    File: internal/storage/routing_table.go (modify)
    
    Current: map[CID] → {ProviderID, RepVector} (single provider per CID)
    Required: map[Key] → [{ProviderID1, ProviderID2, ...}, RepVector] (multiple providers per key)
    
    Tasks:
    [x] Change RoutingTableEntry to use Key instead of CID as primary identifier
    [x] Change ProviderID field to []peer.ID (multiple providers per key)
    [x] Update Set() to append providers (not replace) for same key
    [x] Add AddProvider(key Key, providerID peer.ID) method
    [x] Add RemoveProvider(key Key, providerID peer.ID) method
    [x] Add GetProviders(key Key) []peer.ID method
    [x] Update all call sites to use Key instead of CID for routing table operations

1.3 Data Structure Update
    -----------------------
    File: internal/storage/store.go (modify)
    
    Required: "remove the device id from the data hashing only hash the data and then 
    alter the data structure to have the device id added in to it"
    
    Tasks:
    [x] Create KeyedBlock structure: {Key, Data, ProviderID, CID}
    [x] Update PutRawBlockIndexed to return (Key, CID) tuple
    [x] Store Key → ProviderID mapping separately from data
    [x] Ensure ProviderID is NOT included in key hash calculation
    [x] Update GetBlock to accept Key as primary parameter
    [x] Create GetBlockByKey(key Key) method (primary method)

PHASE 2: TOKEN-BASED ROUTING ARCHITECTURE
================================================================================
Goal: Transform DHT to route tokens (containing physical locations) instead of 
directly routing data/provider announcements.

2.1 Token Structure Definition
    ---------------------------
    File: internal/storage/token.go (new)
    
    Required: "we want dht to route tokens. tokens should contain physical location 
    of data. we want to add the key to dht."
    
    Tasks:
    [x] Define Token struct:
        - Key: Key (hash of data)
        - Locations: []Location (physical locations: peer.ID + multiaddr)
        - Timestamp: int64
        - Version: int (for conflict resolution)
    [x] Define Location struct:
        - ProviderID: peer.ID
        - Address: multiaddr.Multiaddr
        - RTT: time.Duration (optional, for selection)
    [x] Implement Token.Marshal() and Token.Unmarshal()
    [x] Implement Token.Validate() (check key, locations not empty)
    [x] Token is stateless (per newReqs.txt: "the key, the dht hash key has no state")

2.2 DHT Token Routing
    ------------------
    File: internal/storage/token_routing.go (new)
    
    Required: "dht routes tokens. tokens should contain physical location of data"
    
    Tasks:
    [x] Implement PutToken(ctx, key Key, token Token) error
        - Stores token in DHT using key as DHT key
        - Token contains locations, not data
    [x] Implement GetToken(ctx, key Key) (Token, error)
        - Retrieves token from DHT
        - Returns locations for direct device-to-device fetch
    [x] Implement UpdateTokenLocations(ctx, key Key, locations []Location) error
        - Updates token with new locations (for replication)
    [x] Use DHT namespace: "/tokens/" + hex(key)
    [x] Token TTL: 48 hours (per libp2p DHT standard)

2.3 Data Retrieval Flow Transformation
    ------------------------------------
    File: internal/storage/store.go, internal/control/server.go (modify)
    
    Current Flow:
    1. Get request → DHT FindProviders → Bitswap fetch
    
    Required Flow:
    1. Get request → DHT GetToken(key) → Token contains locations → Direct fetch from devices
    
    Tasks:
    [x] Update GetBlock to:
        - Accept Key parameter
        - Call GetToken(key) to get locations
        - Try direct fetch from each location (parallel)
        - Return error if token not found
    [x] Update /get endpoint to:
        - Extract key from request
        - Use token-based routing exclusively
    [x] Implement DirectFetch(ctx, location Location, key Key) ([]byte, error)
        - Opens direct stream to provider
        - Requests data by key
        - Returns data or error

2.4 Token Synchronization
    ------------------------
    File: internal/storage/token_sync.go (new)
    
    Required: "the only function of the token is to sync with the data"
    
    Tasks:
    [x] Implement TokenSync protocol:
        - When data is stored locally, create/update token
        - When data is deleted, remove token (or mark as deleted)
        - When replication occurs, update token with new locations
    [x] Auto-sync token on Put operations
    [x] Auto-sync token on Delete operations
    [x] Auto-sync token on Repair operations (add new replica locations)
    [x] Token versioning for conflict resolution

================================================================================

    [x] Define KeyLock struct:

        - AcquiredAt: time.Time
        - ExpiresAt: time.Time
        - Version: int (for conflict resolution)
    [x] Implement KeyLockManager:
