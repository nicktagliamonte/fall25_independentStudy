Scaling Analysis Plots Explanation
====================================

This document explains what the three plots in scaling_analysis.png show and how to interpret them.

Plot 1: Convergence Time vs Network Size
-----------------------------------------
What it shows:
  How long it takes for the network to stabilize (reach steady state) as we add more nodes.

What to look for:
  - Flat line: Convergence time stays constant regardless of network size (excellent scaling)
  - Slight upward slope: Convergence time grows slowly with network size (good scaling)
  - Steep upward slope: Convergence time grows quickly with network size (poor scaling)

What it means:
  - If convergence time stays around 30-50 seconds for 5 nodes and 500 nodes, the system scales well
  - If convergence time jumps from 30s to 300s as nodes increase, there's a scalability bottleneck
  - The y-axis is fixed at 30-90 seconds to make small differences easier to see

Real-world interpretation:
  - Constant convergence time means the network can handle growth efficiently
  - Growing convergence time suggests the system may struggle at larger scales


Plot 2: Restores per Node vs Network Size
------------------------------------------
What it shows:
  How many restore operations each node performs on average as the network grows.

What to look for:
  - Constant value (e.g., ~1.0): Each node does the same amount of work regardless of network size (ideal)
  - Decreasing value: Work is distributed better as network grows (good)
  - Increasing value approaching 1.0: Expected in star topology (see explanation below)

What it means:
  - In a star topology, the bootstrap node (node 1) has the data and doesn't need to restore
  - All leaf nodes (nodes 2-N) restore the data from the bootstrap
  - Restores per node = (number of leaves) / (total nodes) = (N-1)/N
  - As N grows: N=5 → 0.8, N=10 → 0.9, N=20 → 0.95, N=100 → 0.99
  - This approaches 1.0 as the network grows large

Why this pattern appears:
  - With 5 nodes: 4 leaves restore, 1 bootstrap doesn't → 4/5 = 0.8 restores per node
  - With 100 nodes: 99 leaves restore, 1 bootstrap doesn't → 99/100 = 0.99 restores per node
  - The bootstrap node "dilutes" the average, but its effect decreases as N grows

Real-world interpretation:
  - This is EXPECTED behavior for star topology - not a problem
  - It means the restore workload is correctly distributed to leaf nodes
  - The increasing trend toward 1.0 indicates the bootstrap overhead becomes negligible at scale


Plot 3: Complexity Analysis (Log-Log)
-------------------------------------
What it shows:
  How the total number of dials grows as we add nodes, compared to theoretical complexity classes.

What to look for:
  - Line parallel to O(n): Linear scaling - dials grow proportionally with nodes (best case)
  - Line between O(n) and O(n²): Somewhere between linear and quadratic (acceptable)
  - Line parallel to O(n²): Quadratic scaling - dials grow much faster than nodes (problematic)

What it means:
  - O(n) scaling: Adding 10x nodes means 10x dials (efficient)
  - O(n log n) scaling: Adding 10x nodes means ~23x dials (acceptable for many systems)
  - O(n²) scaling: Adding 10x nodes means 100x dials (inefficient, won't scale)

Real-world interpretation:
  - Linear or near-linear scaling means the system can handle large networks efficiently
  - Quadratic scaling means the system will struggle with large networks
  - The log-log plot makes it easy to see which complexity class the system follows

How to read log-log plots:
  - Both axes use logarithmic scales (powers of 10)
  - A straight line indicates a power-law relationship
  - The slope of the line tells you the exponent (steeper = worse scaling)


Summary: What Good Scaling Looks Like
--------------------------------------
- Convergence time: Flat or slowly increasing line
- Restores per node: Constant or decreasing line
- Complexity: Line close to or parallel to O(n) reference

If all three plots show these patterns, your system scales well and can handle large networks efficiently.
